# StaticTableGenerator

An offline code-generation console tool. It is not part of the runtime API/website —
run it manually whenever certain source files change. It reflects/parses over the
codebase and regenerates several auto-generated C# (and one Python) files, writing its
output back into `Library/Data/`.

Entry point: [`Program.cs`](Program.cs).

## What it generates

On each run ([`Program.cs:86-100`](Program.cs#L86-L100)) it performs four tasks:

1. **Metadata static table** — parses `Library/Logic/Calculate/Calculate.cs` via Roslyn
   (see `ExtractSummaries`, [`Program.cs:603-678`](Program.cs#L603-L678)) to pull each
   Open API calculator method's XML-doc summary/param comments, then generates
   `Library/Data/OpenAPIStaticTable.cs` — a static list of `OpenAPIMetadata` giving every
   API method's signature, line number, param docs, and description. This lets the Open
   API surface carry metadata without needing reflection/doc-parsing at runtime.

2. **Python calculate stub file** — from that same metadata, generates a `.pyi` type-stub
   file for the `VedAstro.Python` package's `Library.pyi`, so Python users get
   autocomplete/type hints matching the C# `Calculate` methods.

3. **Event data static table** — reads `Library/XMLData/EventDataList.xml` and generates
   `Library/Data/EventDataListStatic.cs`, converting the XML event definitions into a
   static C# list of `EventData`. This step also calls an LLM (a hosted
   `/SummarizePrediction` endpoint) to classify each event's description into a
   specialized sentiment summary per life category (Mind/Studies/Family/Money/Love/Body),
   caching results by SHA-256 hash to a CSV (`AI-MADE-DATA/AI-prediction-cs-safety-cache.csv`)
   to avoid repeat/paid calls.

4. **Horoscope data static table + enum** — same idea but for
   `Library/XMLData/HoroscopeDataList.xml`, generating
   `Library/Data/HoroscopeDataListStatic.cs` and the `HoroscopeName` enum.

## Summary

It's a build-time/dev-time data compiler that turns XML data files and doc comments into
strongly-typed static C# (and Python stub) code, so the app doesn't parse XML or reflect
over doc comments at runtime. All output files are marked
`AUTO GENERATED ... DO NOT EDIT DIRECTLY, USE STATIC TABLE GENERATOR IN MAIN REPO` and
should only be regenerated by re-running this tool.
